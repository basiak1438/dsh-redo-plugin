# dsh-redo

DeepSeek Harness 插件：**改掉已经发出去的那句话，再重发一次**。

不需要开新会话，也不需要手动"回退 → 复制原文 → 改 → 再发"。在任意一条提问旁点「订正」，就地改完确认，撤回与新发送一次完成。

> [!NOTE]
> **完全独立运作，零外部插件依赖。**
> 从 v0.2.0 起，dsh-redo 内置了完整的文件写前快照引擎（SnapshotStore）与聊天视图隐藏管理器（VisibilityBuilder），不再需要安装或依赖任何第三方插件即可独立提供全部能力。

## 它解决什么

两个真实场景：

1. **提交后发现笔误**——句子有歧义，模型已经开始答了，想撤回来改一个字。
2. **答完发现方向偏了**——模型顺着错误的理解做完了一轮，连带改了一堆文件，想把这一切退回去重新提问。

两者在插件看来是同一件事：目标消息及之后的全部内容一起撤掉（可选还原文件），改好的提问重新发送。

## 交互

每条用户消息行旁常驻一个「订正」操作按钮。

点击后：

- **这一段没有文件改动** → 直接弹出居中编辑框，预填原提问；
- **这一段改过文件** → 先列出会被还原的文件清单（`↺ 还原` / `✕ 删除`），确认后再进编辑框。

**在编辑框里点「撤回并发送」之前，什么都不会改变。** 取消 = 零副作用，对话和文件都保持原样。

编辑框的按键与主输入框一致：`Enter` 发送、`Shift+Enter` 换行、带 `Alt`/`Ctrl`/`Cmd` 的组合键不拦截。

确认后宿主依次执行：

1. `/redo-plugin @<seq> chat|both` —— 停止运行中任务，写入遮蔽 marker，必要时还原工作区文件；
2. `session.prompt(content, 'queue')` —— 把改好的文本（连同原图附件）作为新的真实用户消息发出。

## 架构与独立能力

| 能力 | 实现机制 |
|---|---|
| **对话撤回** | 写入标准的 append-only 遮蔽标记（`surfaceOp: replace`） |
| **视图自动隐藏** | 内置 `RedoVisibilityBuilder` 拦截聊天视图，自动将已撤回的旧节点标记为 `visibility: hidden` |
| **工作区文件快照** | 内置 `SnapshotStore`，监听 `tools/execute`，在模型调用 `write`/`edit` 前做原子捕获（落盘于 `~/.dsh/redo-snapshots/`） |
| **文件还原** | 原子还原文件内容并清理本段新增的文件，同步触发文件系统观测事件 |
| **自动重发** | 撤回完成后立即通过 `session.prompt` 唤醒新回合 |

## 已知边界

- **只跟踪 `write` / `edit` 两个工具**——模型用 shell 重定向、`pwsh` 等方式写的文件不会被快照引擎记录，无法回滚；
- **单文件 8 MiB 上限**——超过大小的文件不备份；
- **每个会话只保留最新 100 组**快照——太早的回合没有还原点；
- **`file` 类附件无法重发**——harness 暂无客户端文件字节加载器，只有文本和图片能随订正消息重发；
- **撤回不可逆**——遮蔽是 append-only 的标记。若撤回成功但发送失败，插件会自动把改好的文本回填输入框，避免白写。

## 与 dsh-rewind-plugin 的共存

完全兼容，互不冲突：
- 独立的快照存储目录（`~/.dsh/redo-snapshots/` vs `~/.dsh/rewind-snapshots/`）；
- 视图隐藏层同时支持识别两种插件产生的历史命令；
- 无论单装 `dsh-redo-plugin`，还是两者同时安装，均可正常使用。

## 安装

```sh
dsh plugin --profile <name> add dsh-redo-plugin@<版本>
```

## 开发

本仓库是 `dsh-redo-plugin` 的源码树。安装时以本地目录链接进 profile，无需构建步骤——`lib/index.js` 与 `lib/client.js` 即为运行代码。

```sh
git clone https://github.com/basiak1438/dsh-redo-plugin.git
```
